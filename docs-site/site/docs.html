02 Entorno de desarrollo

Instalación local

En Linux, usa Git, Docker Engine y Compose v2. Node.js, npm, Python, PostgreSQL, FFmpeg y Playwright se ejecutan en contenedores con versiones fijadas. La misma ruta sirve en una laptop o una VM Linux de Azure.

  1. 01

    Clona el desarrollo actual

    Inicia sesión en GitHub con una cuenta que tenga acceso al repositorio.

    Terminal 
    git clone --branch main https://github.com/glender222/whatsap-automat.git
cd whatsap-automat
  2. 02

    Prepara el entorno reproducible

    Ejecuta la entrada común desde la raíz. Prepara la imagen y las dependencias desde sus lockfiles, sin instalar lenguajes en el host.

    Desde la raíz 
    ./dev setup
  3. 03

    Arranca la demo local

    La configuración privada se genera en .dev/local/dev.env, con permisos restringidos y excluida de Git. Conserva los archivos .env existentes. Cambia DEV_WEB_PORT y DEV_API_PORT antes de arrancar si necesitas otros puertos. La demo no requiere claves de proveedores.

    Desde la raíz 
    ./dev up
./dev doctor

    Abre http://localhost:5173 con demo@automat.local y Demo-local-2026!. Usa la API real, JWT y RLS con datos sintéticos de dos empresas. Los puertos se publican solo en localhost.

  4. 04

    Comprueba y conserva tus datos

    Valida el código y el recorrido web, incluido el aislamiento de empresas y la persistencia tras reiniciar. Cada checkout tiene sus propios volúmenes; down los conserva.

    Desde la raíz 
    ./dev check
./dev smoke
./dev down

    Consulta la guía de desarrollo para Azure, móvil, Temporal opcional y proveedores reales. Clonar o arrancar la demo no activa integraciones externas.

04 Integraciones

API y SDK

Importa OpenAPI en tu cliente HTTP o generador de código. Con la API local activa, puedes abrir el visor en http://localhost:3000/api/v1/docs.

Autenticación
Envía un JWT válido con Authorization: Bearer … en rutas privadas.
Reintentos
Los SDK reintentan lecturas y operaciones con clave de idempotencia. Reutiliza el mismo Idempotency-Key para repetir una operación compatible.
Conflictos
Si una mutación con expectedVersion devuelve 409, recarga el recurso antes de decidir si procede otro intento.
Adjuntos
Consulta los IDs de mensaje y archivo en el historial para descargarlos con tu sesión. El envío multipart requiere una clave de idempotencia y la versión vigente de la conversación.

05 Verificación

Pruebas y estado de entrega

Comprueba la ejecución de CI del commit que vas a usar. Para integrar cambios, la guía de QA exige evidencias por módulo, aislamiento entre empresas y validación de los flujos críticos.

Desde la raíz, tras instalar dependencias 
npm --prefix packages/contracts test
npm --prefix WhatsaapWeb-JS run typecheck
npm --prefix WhatsaapWeb-JS run typecheck:scripts
npm --prefix WhatsaapWeb-JS test
npm --prefix Frontend_py_whatsaapweb run build
npm --prefix Frontend_py_whatsaapweb test

Alcance de Mercado Pago

La conciliación interna es administrativa y está deshabilitada por defecto. Requiere configurar credenciales por empresa y habilitar MERCADOPAGO_RECONCILIATION_ENABLED. Registra pagos pendientes, parciales, liquidados y devueltos; un pago parcial no confirma el pedido.

El piloto con una cuenta peruana autorizada sigue pendiente. El checkout público y la recepción de webhooks están pendientes de implementación y validación.

Proveedores y móvil

Las pruebas con proveedores locales no sustituyen la validación de Meta con dos líneas autorizadas ni el piloto real de IA. El APK ARM64 es un candidato de QA y requiere pruebas en dispositivo antes de distribuirse para producción.

Las pruebas locales cubren los casos documentados de cada suite. Comprueba por separado la conexión con proveedores, la migración en una base limpia y la instalación en dispositivos.
